# Platform language and RITVAYAM audit — 25 October 2026

The earlier shared-control release centralized preference ownership, but did not
provide complete interface localization. This follow-up audited 30 anonymous
page routes against the real Node composition, plus the production asset export.
Only isolated temporary DATA_DIR fixtures were used. No production records were
read or changed for the audit.

## Problems found and corrected

- Gujarati was conditionally added only for a Vedic adapter or an existing Gujarati
  preference. The shared menu now always presents English, Hindi and Gujarati.
- Several local tools had the shared header but no language script or footer.
  `legalHtml()` now ensures that every shared-header page loads the same service
  exactly once, including pages without a footer.
- Only header/home roots were translated; other pages could retain English document
  language. The shared service now translates catalogued interface text and
  attributes in page content, with explicit exclusions for records and outputs.
- Incoming `?lang=en` could override a retained Gujarati/Hindi preference. A valid
  saved global preference now wins; a URL seeds the preference only when no valid
  saved preference exists. Existing language query parameters are synchronized
  after native app renders as well as deliberate changes.
- Gujarati calendar rendering was missing from the home feature. Date, lunar
  month, tithi labels and calendar status now support it without changing numbers.
- The beta notice owned another English/Hindi control and preference path. It
  now temporarily hosts the existing shared menu while its modal is open, then
  returns that same element to the header. Notice copy supports all three
  languages; acknowledgement rules are unchanged.

## Shared implementation

`packages/ui/language-runtime.js` is the source owner. The authored
`interface-copy.mjs` contains 993 English/Hindi/Gujarati interface entries;
the existing Hindi dictionary remains available for older copy. One local
`language.js` bundle is generated by `infrastructure/build-language.cjs`, invoked
from the existing frontend build. There are no translation requests, new external
services, per-page menu implementations or additional preference keys.

The existing theme bootstrap initializes the saved document language before page
content is parsed. Explicit language changes, dynamic UI updates, pageshow and
cross-tab preference changes use the same shared service and observer. Processing
is limited to dirty DOM subtrees for normal updates. Native Vedic translations
remain app-owned through the existing adapter, preserving entered birth details.
Ritual's existing English/Hindi native state remains a compatibility source for
Gujarati interface rendering; the visible preference stays Gujarati. Samaj uses
the shared Gujarati catalogue for known interface keys without translating raw
record values.

Names, numbers, input values, custom checklist items, wheel choices, tasks,
feedback submissions/comments, confession messages, news articles, canvas artwork,
private record values and print/export documents retain their own content.
App brands retain their names. Uncatalogued prose and original legal/source
documents stay in their original language and are not silently sent for machine
translation. This is expanded UI localization and preference retention, not a
claim that every paragraph or private workflow has independent translation review.

## RITVAYAM

The astrology app is named **RITVAYAM** in the registry, navigation, home feature
and document titles. Its stable app ID and `/rashifal-kundli` routes are preserved
to retain links and access semantics. The home feature has an original inline
lotus/crescent/orbit mark using shared theme tokens, with a compact mobile layout.

Gochar-8's daily summary addresses the selected Rashi's readers in a familiar
traditional register, including “मेष राशि के जातकों” / “મેષ રાશિના જાતકો”.
Authored prose follows the calculated house themes and retains two themes when
the period changes. It no longer leads with an arrow-separated list of editorial
headings or repeated theme cards. Work, spending and relationship suggestions,
calculation disclosure and uncertainty behavior remain. No Pandit authorship,
certification, new traditional rule validation or guaranteed event is claimed.
The numerical engine is unchanged. The worker bundle excludes birth/place modules
by an explicit build-input assertion, with a 220 KB bound accommodating the
three-language prose (actual fixture bundle 205,456 bytes).

Verification and the deployed Worker are recorded in the functionality ledger.
