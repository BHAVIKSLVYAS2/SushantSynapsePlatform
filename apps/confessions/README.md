# Confessions

Public route: `/confessions`. A shared stream of separate scratch-to-reveal cards
with a composer below the scrollable conversation. Tap reveal is the accessible
alternative; mouse and phone pointer scratching use the same reveal allowance.

Anonymous submissions send only `{message}` (3–600 characters). New entries are
pending and visible only to the submitting tab and signed-in platform Owners.
An Owner signs in through the existing platform account, opens Confessions and
uses the review queue to approve or remove entries. Reports immediately remove
approved entries from public reads until another Owner review. No author name,
account ID, email, browser ID or IP is attached to stored entries. Hosting/network
logs and transient rate-limit keys can still contain technical information.

Storage uses the existing SQL `settings` table under `confessions-v1`, with a
versioned, bounded envelope of at most 300 entries. Node uses the platform SQLite
transaction; Cloudflare uses the existing D1 guarded commit/revision protocol.
No new database or schema migration is required. All entries become unavailable
after seven days; expired entries are physically pruned on the next successful
write. At capacity, posting returns an explicit error rather than losing a draft
or overwriting records. Six anonymous writes/minute are allowed per network key.
The new Cloudflare `CONFESSIONS_LIMITER` binding is defined in fullstack/free
staging and free production configs. Missing binding fails closed on writes.

Public listing returns only IDs and times. Text is fetched when revealing a
published card; drafts and pending text never appear in public responses.
The session-only reveal ledger stores card IDs and allowance, never messages.
Five new reveals are initially free. Completed rewarded ads grant another five;
re-reading a previously opened card uses no allowance. Unconfigured/unavailable
ads grant the next batch without blocking. The allowance is a browser UX counter,
not a secure paywall. Scratch covers do not encrypt messages. Sample cards are
explicitly labelled examples, stay in the tab and do not use the allowance.

## Advertising status

Header/footer responsive inventory and a desktop-only side placement are built,
separated from posting/reveal actions, lazy-loaded and never auto-refreshed.
Unfilled/unconfigured placements collapse. The optional rewarded-ad dialog only
appears after five new reveals and a real Google readiness event. Grants depend
on Google's reward event; closing an incomplete ad does not grant a batch.
Visitors must opt in before any new ad request.

Advertising remains **disabled** in `frontend/ad-config.mjs`. The repository has
publisher `ca-pub-1894051755496526`, but no manual display slot IDs or Google Ad
Manager rewarded unit path. Google account approval, unit inventory, regional
consent settings and revenue are not established by that publisher code.

Automatic approval review rejected extending the existing broad homepage ad CSP
to Confessions. That change was not applied; the Node attempt was removed and
Cloudflare was left unchanged. The current page retains `script-src 'self'`.
Enabling external ad scripts requires explicit approval of a concrete page-only
security change, real unit configuration and testing with test inventory. No
ad requests/impressions were generated by verification; rewarded events were
mocked locally. Do not set `enabled:true` until those prerequisites are complete.

Verification uses `tests/confessions.test.js`, this app's Playwright suite, and
the native Worker/D1 subtest in `tests/cloudflare-fullstack.cjs`. All seeded data
is confined to temporary DATA_DIR fixtures. Production confessions are never
seeded or reset by these tests.
