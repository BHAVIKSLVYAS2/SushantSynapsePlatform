# photo-resize

Decodes JPEG/PNG/WebP locally (12 MB and 24 MP limits). Default proportional fit preserves the whole image, bounds requested dimensions and can reduce dimensions further to meet a maximum KB. Exact crop preserves the chosen pixel dimensions and fails explicitly if its maximum bytes cannot be reached. Crop positions, zoom and 90-degree rotations are reviewed beside a mobile-friendly canvas; enlarging needs explicit opt-in and warns that no detail is restored.

Output can be JPEG, PNG or WebP when supported by the browser. JPEG makes transparency white; PNG/WebP preserve it. Unsupported format export fails rather than silently returning another MIME type. Canvas omits source EXIF/GPS metadata; explicitly requested JPEG JFIF density is written for print size. DPI changes metadata, not resolution or quality. Minimum/maximum byte, dimensions, format and optional print-density checks describe digital suitability, never government acceptance or automatic face/blur approval. Undersized output is clearly marked and downloadable only as a review image; no filler/noise is added to fake compliance.

The source-linked Indian e-Visa profile uses square JPEG; 600px is our working choice, not an official minimum. For signatures and other forms, use custom settings copied from current official instructions. The expired SSC CHT 2026 preset has been removed. No universal government acceptance preset is claimed. Source URL/check date are in `frontend/profiles.mjs`. Custom KB means 1024 bytes; the e-Visa maximum conservatively uses 1,000,000 bytes.

Live estimates use one debounced local encode at 85% quality and are labelled estimates; final checks use actual bytes. Encoding is cancellable between asynchronous steps, stale output cannot be downloaded, and a separate source revision lets users change settings while a selected file is still decoding. No image upload, image persistence, new API or dependency is added. Batch processing/background removal/identity approval are not part of this pass: per-image crop review and bounded phone memory take priority. Shared page services may still use the network.

Verification: `node --test tests/photo-form-ready.test.js`; `npx.cmd playwright test apps/photo-resize/tests/browser.spec.js`. Existing fit-mode compatibility remains covered by `apps/qr-maker/tests/browser.spec.js`. All browser fixtures use isolated temporary DATA_DIR values. Audit/research: `docs/CURIO_PRODUCT_AUDIT.md`, `docs/CURIO_GROWTH_OPPORTUNITIES.md`. Release status is recorded in the functionality ledger.

App-owned frontend, public registry entry and static allowlist. Shared presentation and download/copy helpers are in packages/ui/local-tools.*. No backend, database schema or provider setup is required. Deployed and live-verified on 2026-10-16; release details are in docs/FUNCTIONALITY_LEDGER.md.
